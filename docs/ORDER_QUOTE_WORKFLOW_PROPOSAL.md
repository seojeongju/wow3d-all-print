# 주문 관리 · 견적서 검토/발송 및 처리 절차 고도화 제안

## 1. 현재 구조 요약

- **주문 상태**: `접수 대기` → `주문 확인` → `제작 중` → `배송 중` → `완료됨` / `취소`
- **자동 견적**: 주문 시 `order_items` ↔ `quotes` 연동, 고객이 본 자동 견적 금액이 `orders.total_amount`에 저장됨
- **전문가(수정) 견적**: 관리자가 입력한 금액/내역은 `orders.expert_quote_data`(JSON), `has_expert_quote`로 구분
- **관리자 기능**: 주문 목록 조회, 상태 변경, **파일 다운로드**(자동 견적된 STL 등), **견적서 인쇄**(`/print/estimate/[id]`), 관리자 메모, 제작 중 전환 시 수정 견적 금액 확인 다이얼로그

**부족한 점**  
- “자동 견적 → 전문가 검토 → 견적서 발송”이 하나의 흐름으로 드러나지 않음  
- 견적서를 **고객에게 발송**하는 버튼/기능 없음  
- 상태만으로는 “견적 검토 중 / 견적 발송 완료”를 구분하기 어려움  
- 검토·발송 후 다음 단계로 넘어가는 반자동/자동 처리 없음  

---

## 2. 제안 1: 주문 상태 확장 (선택)

| 현재 | 제안 추가 (선택) | 용도 |
|------|------------------|------|
| 접수 대기 | (유지) | 주문 접수 직후 |
| — | **견적 검토 중** (`quote_review`) | 전문가가 자동 견적 파일/금액 검토 중 |
| — | **견적 발송 완료** (`quote_sent`) | 견적서를 고객에게 발송함 |
| 주문 확인 | (유지) | 고객 확인/결제 반영 후 |

- **장점**: 목록/필터에서 “아직 견적 안 보낸 주문”을 한눈에 구분 가능, 대시보드·리포트에 활용 가능  
- **단점**: 상태 값이 늘어나고, 기존 “접수 대기”만 쓰는 흐름과의 호환 정책(마이그레이션) 필요  

**대안**: 상태는 그대로 두고, **플래그만 추가**  
- `orders.quotation_sent_at` (DATETIME, NULL)  
  - NULL = 미발송, 값 있음 = 견적서 발송 일시  
- 목록/상세에서 “견적 발송” 여부는 이 컬럼으로 표시·필터

---

## 3. 제안 2: “견적 검토” 전용 UI

- **위치**: 주문 상세 다이얼로그 또는 별도 탭/페이지  
- **구성**  
  1. **자동 견적 요약**  
     - 주문 항목별: 파일명, 출력 방식, 수량, 단가, 소계, **자동 견적 총액**  
     - 기존 “주문 항목” 테이블 + “자동 견적 금액” 강조  
  2. **전문가 검토 액션**  
     - “자동 견적 그대로 사용” / “수정 견적 입력”  
     - 수정 시: 항목별 단가·소계 또는 **총액만** 입력 가능한 폼 (현재 `expert_quote_data` 구조에 맞게)  
     - “검토 완료(저장)” 시 `expert_quote_data` + `has_expert_quote` 갱신  
  3. **견적서 미리보기**  
     - 기존 `/print/estimate/[id]`를 iframe 또는 새 탭으로 띄우기  
     - “인쇄”는 현재처럼 유지, “견적서 발송” 버튼은 아래 4와 연동  

- **정리**: “자동 견적된 파일/금액 → 전문가가 확인/수정 → 견적서로 확정”이 한 화면에서 이어지도록 구성  

---

## 4. 제안 3: “견적서 발송” 기능

- **액션**: 주문 상세에서 **“견적서 발송”** 버튼 클릭  
- **동작**  
  1. (선택) 상태를 `quote_sent`로 변경 또는 `quotation_sent_at` 갱신  
  2. **고객에게 이메일 발송**  
     - 수신: 주문자 이메일 (`user_email` 또는 `guest_email`)  
     - 내용:  
       - 안내 문구 (예: “견적서가 준비되었습니다.”)  
       - **견적서 보기 링크**: `https://도메인/print/estimate/[orderId]` (또는 토큰 포함 단기 유효 URL)  
     - (선택) PDF를 첨부해 발송 (서버에서 PDF 생성 후 첨부)  
  3. 발송 성공 시 토스트/메시지, 실패 시 재시도 또는 관리자 알림  

- **API**  
  - `POST /api/admin/orders/[id]/send-quotation`  
  - Body: (선택) `{ emailOverride?: string, attachPdf?: boolean }`  
  - 응답: `{ success, message, sentAt? }`  

- **보안**  
  - 견적서 URL이 예측 가능하면 남가 주문을 볼 수 있으므로,  
    **단기 유효 토큰**을 쿼리로 붙이거나, **비회원은 이메일 링크 클릭 시 토큰으로만 접근**하도록 권장  

---

## 5. 제안 4: 처리 절차 반자동/자동화

| 구분 | 내용 |
|------|------|
| **1) 접수 시 알림** | 새 주문(접수 대기) 생성 시 관리자에게 이메일/슬랙 등 알림 (선택) |
| **2) 견적서 발송 시 상태/일시 기록** | “견적서 발송” 클릭 시 `quotation_sent_at` 저장 및 (선택) 상태를 `quote_sent`로 변경 |
| **3) 견적 발송 후 안내** | 고객 이메일에 “확인 후 결제/문의” 링크 포함 → 결제나 “주문 확인”으로 이어지도록 유도 |
| **4) 미발송 주문 알림** | 접수 대기 상태로 N시간 경과한데 `quotation_sent_at`이 NULL인 주문을 대시보드/목록에서 강조 또는 주간 리포트로 정리 |
| **5) 상태 전이 가이드** | 상세 화면에 “다음 권장 단계” 표시 (예: 견적 발송 완료 → “주문 확인”으로 변경 권장) |

이메일 발송은 Cloudflare Workers 환경에서는 **외부 이메일 API**(Resend, SendGrid, SES 등) 연동이 필요합니다.  

---

## 6. DB 스키마 변경 (최소)

- **필수**  
  - `orders.quotation_sent_at` (DATETIME NULL) — 견적서 발송 일시  
- **선택**  
  - `orders.status`에 `quote_review`, `quote_sent` 추가하거나, 기존 상태만 쓰고 `quotation_sent_at`으로만 “발송 여부” 관리  

---

## 7. 구현 단계 제안

| 단계 | 내용 | 비고 |
|------|------|------|
| **Phase 1** | 주문 상세에 “견적 검토” 블록 추가 (자동 견적 요약 + 수정 견적 입력 + “검토 완료” 저장) | 기존 `expert_quote_data` 활용 |
| **Phase 2** | `quotation_sent_at` 컬럼 추가, 목록/상세에 “견적 발송” 여부 표시 | 마이그레이션 1개 |
| **Phase 3** | “견적서 발송” 버튼 + `POST /api/admin/orders/[id]/send-quotation` (이메일 발송 + `quotation_sent_at` 갱신) | 이메일 서비스 연동 필요 |
| **Phase 4** | (선택) 상태값 `quote_review` / `quote_sent` 추가 및 필터/배지 반영 | |
| **Phase 5** | (선택) 미발송 오래된 주문 강조, 관리자 알림, 다음 권장 단계 안내 | |

---

## 8. 요약

- **자동 견적된 파일**은 이미 “파일 다운로드”로 확인 가능하고, **전문가 수정 견적**은 `expert_quote_data`로 저장되고 있음  
- 여기에 **“견적 검토” 전용 UI**와 **“견적서 발송”** 버튼·API를 넣고, **발송 일시(`quotation_sent_at`)** 로 처리 이력을 남기면,  
  “자동 견적 → 전문가 검토 → 견적서 발송” 흐름이 명확해지고, 이후 알림·대시보드·자동화를 단계적으로 붙이기 좋습니다.  

원하시면 Phase 1·2·3부터 구체적인 API 스펙과 화면 와이어프레임으로 더 쪼개서 정리할 수 있습니다.
